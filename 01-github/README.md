## 📝 Markdown

O README do GitHub é escrito em **Markdown**, uma linguagem de marcação simples que vira texto formatado.

| O que quero | Como escrever |
|-------------|---------------|
| Título | `# Título`, `## Subtítulo`, `### Seção` |
| **Negrito** | `**texto**` |
| *Itálico* | `*texto*` |
| Lista | `- item` |
| Lista numerada | `1. item` |
| Link | `[texto](https://endereco.com)` |
| Imagem | `![descrição](endereco-da-imagem)` |
| Código na linha | `` `codigo` `` |
| Bloco de código | três crases (```` ``` ````) antes e depois |
| Citação | `> texto` |
| Tabela | colunas separadas por `\|` |
| Tarefa | `- [x] feita` e `- [ ] pendente` |

Exemplo de bloco de código com linguagem:

````markdown
```python
print("Olá, GitHub!")
```
````

Além do Markdown, o GitHub aceita **HTML** dentro do README, o que ajuda a centralizar elementos e a controlar o tamanho de imagens:

```html
<p align="center">
  <img src="https://skillicons.dev/icons?i=python,git" />
</p>
```

## ⭐ 5 coisas que aproveitei do vídeo

1. **Repositório com o mesmo nome do usuário:** criar um repositório **público** chamado `ybryz` com um `README.md` faz o conteúdo aparecer direto no topo do perfil.
2. **Perfil completo:** preencher foto, bio, local e contatos em *Edit profile* deixa o perfil mais confiável. A foto de perfil deve ser minha ou uma arte que eu tenha direito de usar.
3. **Markdown como base:** entender títulos, listas, links e imagens permite montar o README do jeito que eu quiser.
4. **Badges e ícones de tecnologias:** o [skillicons.dev](https://skillicons.dev) e o [shields.io](https://shields.io) mostram as minhas skills de forma visual e organizada.
5. **Inspiração sem copiar:** a lista [awesome-github-profile-readme](https://github.com/abhisheknaiidu/awesome-github-profile-readme) mostra muitos exemplos. Usei como referência e escrevi o meu README com o meu conteúdo.
